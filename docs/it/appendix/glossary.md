# Glossario

| Termine | Uso in questa revisione |
|---|---|
| Authn | Autenticazione: chi ha provato il possesso della credenziale |
| Authz | Autorizzazione: quel principal può fare quell'azione su quegli oggetti? |
| Principal / subject | Identità stabile verificata, distinta da ID dichiarato nel payload |
| Acting for | Rappresentanza di un'organizzazione verificata tramite delega |
| Controller amministrativo | Soggetto che gestisce accessi/controllo della risorsa; concetto proposto |
| primaryAccountable | Responsabilità economica ValueFlows, non ACL |
| custodian | Custodia della risorsa, non amministrazione universale |
| PEP | Policy Enforcement Point nel servizio/dominio che impone la decisione |
| PDP | Policy Decision Point; proposto nel modulo Zenflows |
| RBAC / ABAC / ReBAC | Policy basata rispettivamente su ruoli, attributi e relazioni |
| BOLA / IDOR | Accesso o modifica per ID di oggetto senza autorizzazione adeguata |
| BFLA | Accesso a una funzione privilegiata senza diritto |
| DID | Identificatore decentralizzato; risolverlo non equivale a verificare un permesso |
| Zenroom / Zencode | Runtime crittografico e linguaggio dei contratti |
| Restroom | Servizio HTTP di esecuzione contratti usato da Zenflows |
| DPP | Digital Product Passport, distinto dal listing commerciale |
| TOCTOU | Stato/permesso cambia tra controllo e uso |
| Epoch / fencing | Versione di autorità usata per invalidare decisioni o scrittori obsoleti |
| Fail-closed | Guasto/decisione ignota non concede accesso |
| Outbox | Registrazione durevole di eventi nella transazione locale, consegna successiva |
| Idempotenza | Ripetizione della stessa operazione non produce un secondo effetto |
| PROPOSED | ADR da discutere, non accettato dal team |
